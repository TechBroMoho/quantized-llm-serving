usage: lm-eval run --model <model> --tasks <task> <task> --model_args <arg=value> <arg=value> [options]

Evaluate language models on various benchmarks and tasks.

options:
  -h, --help            show this help message and exit

configuration:
  --config <path>, -C <path>
                        Set initial arguments from YAML config

model and tasks:
  --tasks <task> [<task> ...], -t <task> [<task> ...]
                        Space (or comma-separated) list of task names or
                        groupings. Use 'lm-eval list tasks' to see all
                        available tasks.
  --model <model>, -M <model>
                        Model name (default: hf)
  --model_args <arg> [<arg> ...], -a <arg> [<arg> ...]
                        Model arguments as 'key=val,key2=val2' or `key=val`
                        `key2=val2`
  --apply_chat_template [<template>]
                        Apply chat template to prompts (optional template
                        name)
  --limit <limit>, -L <limit>
                        Limit examples per task (integer count or fraction)
  --use_cache <path>, -c <path>
                        Path to cache model responses (skips repeated
                        inference)

evaluation settings:
  --num_fewshot <n>, -f <n>
                        Number of examples in few-shot context
  --batch_size <size>, -b <size>
                        Batch size: 'auto', 'auto:N' (auto-tune N times), or
                        integer (default: 1)
  --max_batch_size <n>  Maximum batch size when using --batch_size auto
  --device <device>     Device to use (e.g. cuda, cuda:0, cpu, mps)
  --gen_kwargs <arg> [<arg> ...]
                        Generation arguments as `temperature=0,stop=["stop"]`
                        or `key=val` `key2=val2`.Values should be parsable
                        with ast.literal_eval.

data and output (see also: --limit):
  --output_path <path>, -o <path>
                        Output dir or json file for results (and samples)
  --log_samples, -s     Save all model outputs and documents for post-hoc
                        analysis
  --samples <json>, -E <json>
                        JSON mapping task names to sample indices, e.g.
                        '{"task1": [0,1,2]}'. Incompatible with --limit.

caching and performance (see also: --use_cache):
  --cache_requests {true,refresh,delete}
                        Cache preprocessed prompts (true|refresh|delete)
  --check_integrity     Run task test suite validation

instruct formatting (see also: --apply_chat_template):
  --system_instruction <text>
                        Add custom system instruction.
  --fewshot_as_multiturn [<bool>]
                        Use fewshot as multi-turn conversation. Auto-enabled
                        with --apply_chat_template. Use 'false' to disable.

task management:
  --include_path <path>
                        Additional directory for external tasks

logging and tracking:
  --verbosity <level>, -v <level>
                        (Deprecated) Log level. Use LMEVAL_LOG_LEVEL env var
                        instead
  --write_out, -w       Print prompts for first few documents
  --show_config         Display full task configuration after evaluation
  --wandb_args <args> [<args> ...]
                        Weights & Biases init arguments key=val key2=val2
  --wandb_config_args <args> [<args> ...]
                        Weights & Biases config arguments key=val key2=val2
  --hf_hub_log_args <args> [<args> ...]
                        Hugging Face Hub logging arguments key=val key2=val2

advanced options:
  --predict_only, -x    Save predictions only, skip metric computation
  --seed <seed>         Random seeds for python,numpy,torch,fewshot (default:
                        0,1234,1234,1234). Use single integer for all, or
                        comma-separated list of 4 values. Use 'None' to skip
                        setting a seed. Example: --seed 42 or --seed
                        0,None,8,52
  --trust_remote_code   Allow executing remote code from Hugging Face Hub
  --confirm_run_unsafe_code
                        Confirm understanding of unsafe code execution risks
  --metadata <arg>      `key=val` `key2=val` args parsable by ast.literal_eval
                        (merged with model_args), required for some tasks such
                        as RULER

examples:
  # Basic evaluation with HuggingFace model
  $ lm-eval run --model hf --model_args pretrained=gpt2 dtype=float32 --tasks hellaswag

  # Evaluate on multiple tasks with few-shot examples
  $ lm-eval run --model vllm --model_args pretrained=EleutherAI/gpt-j-6B --tasks arc_easy arc_challenge --num_fewshot 5

  # Evaluation with custom generation parameters
  $ lm-eval run --model hf --model_args pretrained=gpt2 --tasks lambada --gen_kwargs temperature=0.8 top_p=0.95 'stop=["\n\n"]'

  # Use configuration file
  $ lm-eval run --config my_config.yaml --tasks mmlu

For more information, see: https://github.com/EleutherAI/lm-evaluation-harness
